Documentation de l'API REST v1

Connectez vos agents autonomes en quelques lignes de code. L'API VaultGuard évalue chaque intention de paiement, exécute les contrôles du pare-feu et prépare les transactions on-chain.

Authentification

Sécurisation des requêtes par clé Bearer

Toutes les requêtes vers l'API /v1 s'authentifient via l'en-tête standard HTTP Authorization.

Chaque agent dispose d'une clé API unique créée depuis votre espace client (/app). Les clés sont préfixées par vg_live_ ou vg_test_ et sont hashées en SHA-256 en base de données.

Authorization: Bearer vg_test_1234567890abcdef

En cas de suspicion d'intrusion ou de blocages répétés, une clé est automatiquement placée en quarantaine sans révéler d'information interne à un agent éventuellement compromis.

Endpoints

Référence des points d'accès

POST /v1/payments

Soumet une intention de paiement pour analyse par le pare-feu et exécution ou mise en attente.

Paramètres JSON

Champ Type Description
to Chaîne (requis) Adresse EVM du destinataire (format 0x sur 42 caractères).
amount Chaîne (requis) Montant en AVAX sous forme de texte (ex. "0.05"). Les flottants sont strictement refusés pour éviter les pertes de précision.
memo Chaîne (optionnel) Description ou référence de facture (140 caractères maximum).
user_request Chaîne (optionnel) Instruction originale donnée par l'humain à l'agent (utilisée pour valider le mandat).
documents Tableau (optionnel) Liste de documents analysés par l'agent : [{"source": "facture.pdf", "content": "..."}].

Exemple de réponse (200 OK)

{ "id": "pay_a1b2c3d4e5f6", "decision": "allowed", "reasons": [ { "code": "ok", "action": "ALLOW", "title": "Paiement conforme", "detail": "aucune règle déclenchée" } ], "chain": { "status": "Executed" }, "memo": "Facture INV-2026-114" }

Valeurs du champ decision :

  • allowed : Paiement conforme et autorisé.
  • pending_review : Montant supérieur au seuil ou contexte ambigu ; en attente de validation humaine.
  • blocked : Violation de politique ou tentative d'injection détectée.
GET /v1/payments/{id}

Récupère le statut actualisé d'un paiement précédemment soumis. Utilisé par un agent pour vérifier si un paiement en attente a été approuvé ou rejeté par un administrateur.

Exemple de réponse (200 OK)

{ "id": "pay_a1b2c3d4e5f6", "recipient": "0x8ba1f109551bd432803012645ac136ddd64dba72", "amount_gwei": 50000000, "amount_avax": "0.05", "memo": "Facture INV-2026-114", "decision": "allowed", "reasons": [ ... ], "chain_status": "executed", "created_at": 1791298315, "updated_at": 1791298315 }
GET /v1/policy

Retourne les paramètres de politique financière en vigueur pour l'organisation de l'agent.

Exemple de réponse (200 OK)

{ "network": "mock", "vault_address": "", "limits": { "max_tx": "0.1", "max_daily": "0.3", "human_threshold": "0.05", "activation_delay": 86400, "circuit_breaker_limit": 5 }, "active_suppliers": [ { "name": "ACME Cloud Services", "address": "0x8ba1f109551bd432803012645ac136ddd64dba72" } ] }
Statuts

Codes de retour HTTP

L'API utilise des codes HTTP standards pour refléter l'état de traitement sans divulguer de détails sensibles.

Code Signification Description
200 OK Succès La requête est traitée avec succès. La décision de sécurité est contenue dans le corps JSON.
400 Bad Request Paramètres invalides Format d'adresse incorrect, montant non conforme (notation scientifique, négatif), memo supérieur à 140 caractères.
401 Unauthorized Authentification requise Clé API absente, mal formée, inexistante, révoquée ou en quarantaine (message d'erreur unifié).
403 Forbidden Organisation suspendue L'organisation rattachée à la clé a été suspendue par l'administrateur de la plateforme.
404 Not Found Ressource introuvable L'identifiant de paiement demandé n'existe pas ou n'appartient pas à l'organisation de la clé (isolation anti-IDOR).
429 Too Many Requests Débit dépassé Le quota de requêtes par minute alloué à la clé d'agent ou à l'adresse IP a été dépassé.
Intégration

Exemples de code pour vos agents

Exemple en Python (avec le SDK VaultGuard)

Utilisez notre client officiel autonome basé sur la bibliothèque standard Python :

from sdk.vaultguard_client import VaultGuardClient client = VaultGuardClient( api_key="vg_test_secret_key_here", base_url="/v1" ) # Soumission du paiement res = client.pay( to="0x8ba1f109551bD432803012645Ac136ddd64DBA72", amount="0.05", memo="Abonnement serveur #492", user_request="Payer l'abonnement ACME" ) if res["decision"] == "allowed": print("Paiement validé par le pare-feu") elif res["decision"] == "pending_review": print("En attente de confirmation humaine") else: print("Paiement bloqué :", res["reasons"])

Exemple avec curl (CLI)

Pour tester un paiement directement en ligne de commande :

curl -X POST /v1/payments \ -H "Authorization: Bearer vg_test_secret_key_here" \ -H "Content-Type: application/json" \ -d '{ "to": "0x8ba1f109551bD432803012645Ac136ddd64DBA72", "amount": "0.05", "memo": "Facture maintenance ACME", "user_request": "Payer la maintenance ACME" }'
